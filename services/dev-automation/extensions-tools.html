Dev and Automation

Extensions and Internal Tools

Where the Ads console makes a necessary workflow tedious, I build the missing piece rather than paying the tedium tax forever, and everything I build shares one reliable data layer.

The Data Extraction Layer

Every rule I automate is only as trustworthy as the data underneath it, so the foundation of my tooling is the open source data extraction layer that pulls the advertising reports on a schedule and normalizes them into one consistent shape. Amazon's reports arrive in different formats with different retention windows and different quirks, and the extractor absorbs all of that so downstream rules always fire against complete and current numbers instead of a stale export someone downloaded last Tuesday. When the data layer is boring and reliable, everything built on top of it inherits that reliability.

Bulk Tooling and Custom Extensions

Where the Ads console makes a necessary workflow tedious, I build the missing piece rather than paying the tedium tax forever. That means bulk tooling that applies a structured change across hundreds of campaigns in one reviewed pass, and custom extensions that put the missing workflow directly into the tools my team already uses, so nobody has to leave the page they work in to do the job correctly. Building the tool once beats doing the workaround weekly, because a tool encodes the correct procedure while a workaround quietly drifts every time a different person runs it.

Spreadsheet Engines

Clients live in spreadsheets, so I build spreadsheet engines that refresh themselves from the same data layer the automation uses. Pacing trackers, campaign dashboards, and forecast sheets all pull from scheduled data flows rather than manual exports, which means the sheet a founder opens on Monday morning shows the same numbers my rules acted on over the weekend. The sheets keep their formatting and their formulas as they update, because a report that a human reads should look like it was built for a human to read.

What This Produces

The outcome is an operation where the repetitive work runs as code with a paper trail and the humans spend their hours on judgment instead of data entry. Reports stop disagreeing with each other because they share one data layer, bulk changes stop introducing typos because a tool applies them, and the account stops depending on whoever happens to remember the manual procedure that week. This is the internal tooling that lets one operator run accounts at a depth that normally requires a team.
